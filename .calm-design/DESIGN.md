# Design System: Drivacy 모바일 동의 시트

## 0. Brand Philosophy

Drivacy는 보험에 필요한 요약 결과와 보호되는 원본 정보를 사용자가 한눈에 구분하도록 만든다. 핵심 가치는 최소 공개, 이해 가능한 동의, 차분한 신뢰다. 한 화면에는 하나의 명확한 CTA만 두고, 개인정보 관련 문구는 홍보 표현보다 구체적인 데이터 항목을 우선한다.

## 1. Visual Theme & Atmosphere

기존 Figma의 옅은 회색 배경, 흰색 surface, 단일 파란 액센트를 유지한다. 동의 시트는 법률 문서처럼 빽빽하지 않되, 사용자가 체크 전에 처리 목적·제공 항목·제외 항목을 빠르게 훑을 수 있는 차분한 정보 계층을 사용한다.

## 2. Color Palette & Roles

## 3. Typography Rules

React Native에서는 `Pretendard, System`을 우선하며 한국어 단어 중간 줄바꿈을 피한다. 시트 제목은 23px/800, 동의 제목은 14px/700, 세부 설명은 12px/18px로 구분한다. 본문은 최소 400 weight를 유지하고 회색 글자의 대비를 낮추지 않는다.

## 4. Component Stylings

**Consent Card** — Default: 흰 배경·1px border·14px radius. Hover(web): border를 한 단계 진하게. Focus: 2px Accent ring. Active: opacity 0.72. Disabled: opacity 0.5. Loading: 사용하지 않으며 시트 전체 로딩이 필요하면 기존 spinner 패턴을 따른다.

**Primary Button** — Default: Accent 배경·흰 글자·full pill. Hover(web): 밝기만 미세 조정. Focus: Accent ring. Active: opacity 0.76. Disabled: 회색 배경·낮은 대비. Loading: spinner와 기존 CTA 문구를 함께 유지한다.

**Checkbox** — Default: 24px outline. Hover(web): Border 강조. Focus: Accent ring. Active: 눌림 opacity. Disabled: muted 처리. Loading: 해당 없음이며 중복 입력이 생기면 상위 CTA를 잠근다.

## 5. Layout Principles

402×874 기준 bottom sheet의 최대 높이는 88%이며 내용이 넘치면 내부만 스크롤한다. 헤더, 두 개의 동의 카드, 보호 정보 카드, CTA 순서로 읽히게 하고 각 동의 카드 안에서는 체크박스·제목·세부 설명을 하나의 터치 영역으로 묶는다. 최소 터치 영역은 44px이다.

## 6. Depth & Elevation

배경 dim과 흰색 시트의 대비만으로 계층을 만든다. 동의 카드에는 그림자를 사용하지 않고 얇은 border로 묶는다. 시트 상단 모서리는 28px를 유지하며 네온 글로우나 과도한 중첩 그림자는 사용하지 않는다.

## 7. Motion & Interaction

기존 React Native `slide` 모달 전환만 사용하고 별도 반복 모션은 추가하지 않는다. 체크 상태는 즉시 바뀌며 두 필수 항목이 모두 선택될 때 CTA가 활성화된다. 닫기 또는 backdrop dismiss 시 임시 체크 상태를 초기화한다.

## 8. Responsive Behavior

작은 화면에서도 하단 safe area를 보존하고 시트 내용은 ScrollView로 접근 가능해야 한다. 긴 한국어 설명은 flex 축소와 자연스러운 줄바꿈을 허용하며 가로 스크롤은 만들지 않는다. 360×740과 402×874에서 CTA와 마지막 안내 문구가 잘리지 않아야 한다.

## 9. Anti-Patterns

- 체크박스 제목만 두고 처리 목적이나 제공 범위를 숨기지 않는다.
- 실제 보험사 제출이나 Midnight 증명이 수행되는 것처럼 표현하지 않는다.
- 보호 정보와 제공 정보를 한 문단에 섞어 사용자가 차이를 추론하게 만들지 않는다.
- 보라색 그래디언트, 장식용 아이콘, 과도한 카드 그림자를 추가하지 않는다.
- 기존 온보딩 카피, 체크 후 보험 조회 흐름, 필수 동의 2개 구조를 바꾸지 않는다.
