# 화면·Backend 연동 실행 계획 — 2026-09-26

`origin/feat`의 2026-09-25 인계 문서를 기준으로 한다. 기존 fixture 프리뷰는 유지하고, 인증된 API 모드에서만 서버 결과를 보여준다.

1. 현재 모바일·웹 화면의 fixture 상태와 Backend 응답을 매핑한다. 인증/월렛 설정이 없는 환경은 실제 연동 완료로 취급하지 않는다.
2. 가입자 API의 응답을 검증하고 계약·특약·평가기간·운행·처리 상태·신청 상태를 구분하는 통합 경계를 만든다. 안정적인 멱등 키와 ID 기반 복구를 테스트한다.
3. 화면은 API 모드에서 서버 데이터를 사용한다. 주행 결과는 `db-confirmed`에서만 성공으로 전환하고, 나머지 상태는 대기/복구로 표시한다.
4. 보험사 신청 판단은 검증과 적용 결정을 별도로 노출한다. 수기 Rule 입력과 기존 디자인·fixture 경로는 유지한다.
5. 모바일·웹·공유·Backend 관련 테스트, 타입 검사와 빌드를 다시 실행하고 문서 상태를 업데이트한다. 외부 Privy·DB·C·월렛 종단 검증의 미확인 부분을 명시한다.

## 2026-09-26 실행 상태

- 완료: API 주입 시 보험·특약·평가기간, 동일 Session 기록 재생, 안정적인 멱등 키/operation ID 복구, `calculated`/`proving`을 포함한 처리 상태 조회, DB 확정 요약, 가입자 신청과 보험사 VERIFIED 이후 결정을 화면에 연결했다. 가입자 온보딩 요청의 서버 필수 프로필 계약도 수정했다.
- 미완료: 기본 앱·웹 진입점에 Privy 세션이 없으므로 기본 실행은 fixture다. Privy 공식 Expo SDK는 iOS/Android 전용이고 웹을 지원하지 않아 Expo web 미리보기에는 별도 웹 인증 통합이 필요하다. 현재 작업 트리에 앱 ID·모바일 client ID·운영 API/DB/C/가입자 월렛 환경이 없어 실제 OTP 및 E2E를 완료로 주장하지 않는다. 프리뷰 OTP나 고정 Bearer 토큰으로 대신하지 않는다.
- 검증: Shared 34, Rule Draft 38, Backend 206, 모바일 110, 웹 33개 테스트, Backend·모바일·웹 타입 검사, 모바일 lint, 웹 Vite 빌드와 모바일 Expo web export를 실행했다. 실제 Privy OTP·실기기·월렛·체인·DB 종단 검증은 해당 설정 및 실행 환경이 필요하다.
