# 가입자 회원가입 UX · MVP 기준

결정일: 2026-09-23 (KST)

## 확정된 방향

- 가입자의 모바일 회원가입과 로그인에서 **인증하는 항목은 이메일뿐**이다. 이메일 주소로 보낸 6자리 코드를 확인한다.
- 첫 가입자는 이메일 코드 확인 후 이름, 생년월일, 휴대전화 번호를 입력한다. 이 세 항목은 가입자 프로필 정보이며 별도의 실명·명의·휴대전화 인증을 하지 않는다. 솔라피 문자 인증도 이 흐름에 포함하지 않는다.
- 재방문자는 같은 이메일 코드 화면을 거친다. 프로필 저장이 완료된 경우에만 기본 정보 입력을 건너뛴다.
- 웹 보험사 데모의 하드코딩 계정과 가입자 모바일 인증은 별개다.

## 화면 연결

| 상황 | 화면 순서 | 다음 상태 |
| --- | --- | --- |
| 첫 가입 | 이메일 입력 → 6자리 코드 확인 → 기본 정보 입력 → 월렛 안내 → 월렛 생성 → 네트워크 연결 확인 | 연결이 확인된 뒤에만 완료 표시 |
| 재방문, 같은 기기에 월렛 있음 | 이메일 입력 → 6자리 코드 확인 → 기존 월렛 잠금 해제 → 네트워크 연결 확인 | 기본 정보 입력 생략 |
| 이메일 인증 후 프로필 입력을 중단한 경우 | 이메일 입력 → 6자리 코드 확인 → 기본 정보 입력 재개 | Auth 계정 존재만으로 가입 완료 처리하지 않음 |
| 재방문, 기기에 월렛 없음 | 이메일 입력 → 6자리 코드 확인 → 다른 기기 안내 | 새 월렛 자동 생성 없이 중단 |
| 네트워크 연결 실패 | 연결 실패 안내 → 같은 월렛으로 다시 연결 | 이메일 인증과 기본 정보 입력 반복 없음 |

분기는 코드 검증 후 앱이 프로필 저장 완료 여부와 기기 월렛 상태에 따라 결정한다. 분기 선택 버튼은 HTML 레퍼런스의 검토 패널에만 둔다.

## 기본 정보 화면

이름, 생년월일, 휴대전화 번호를 각각 한 입력란에 둔다. 생년월일은 날짜 형식, 전화번호는 번호 형식만 확인한다. 입력값이 틀렸거나 저장에 실패하면 해당 화면에서 수정·재시도하게 하고 이미 적은 값은 유지한다. 주요 버튼은 `정보 입력하고 계속` 하나로 둔다. 전화번호 인증번호 전송 버튼이나 인증 완료 표시는 두지 않는다.

이메일 코드는 이메일 접근만 확인한다. 사용자가 직접 적은 이름·생년월일·전화번호로 실명, 전화번호 명의, 실제 보험 가입 여부를 확인했다고 표현하지 않는다. 실제 보험사 계약 자동 조회도 이 회원가입 흐름에 포함하지 않는다. 예시 보험계약을 보여줄 때는 데모 데이터임을 명확히 표시하고, 임의의 신규 가입자를 기존 예시 계약의 소유자로 자동 연결하지 않는다.

## 설계상 주의점과 개선안

- **정보의 필요성:** 현재 MVP 흐름에는 생년월일·전화번호의 구체적인 사용처가 정해지지 않았다. 가장 간결한 안은 이메일 인증만으로 가입시키고, 실제로 필요한 시점에 해당 정보를 받는 것이다. 이번 레퍼런스에는 요청한 세 입력란을 유지하되, 구현 전 각 항목의 사용 목적·필수 여부·보관 기간·삭제 방법과 수집 안내 문구를 결정해야 한다.
- **보험계약 연결:** 세 입력란을 채웠다는 사실로 데모 보험사에 등록된 계약의 소유자라고 판단할 수 없다. 데모 계약은 미리 지정한 사용자에게만 연결하고, 일반 신규 가입자에게는 예시 데이터 또는 계약 없음 상태를 구분해서 보여준다.
- **중단 후 재개:** 이메일 코드 확인만 끝내고 나간 계정도 존재한다. 다음 로그인 때는 계정 생성 시점이 아니라 프로필 저장 완료 여부를 검사해 정보 입력 화면으로 돌려보낸다.

## 구현 상태와 레퍼런스

[화면 레퍼런스](DRIVER_AUTH_WALLET_UX_REFERENCE.html)는 화면 배치와 전환을 살펴보기 위한 정적 HTML이다. 인증코드 발송, 정보 저장, 실제 월렛 생성·연결을 실행하지 않는다. 현재 `apps/web`의 실행 코드는 이메일·비밀번호 방식이며, 이메일 OTP와 이 기본 정보 입력 화면으로 아직 전환되지 않았다. 이 문서는 그 후속 구현을 위한 UX 결정이다.
