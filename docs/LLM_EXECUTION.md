# 키 입력 없는 클론 환경의 LLM 실행

결정일: 2026-09-16 (KST) · 상태: 구조 확정, 구현·배포 전

## 확정한 기본 방식

심사위원이 레포를 클론하고 앱을 실행하면 **팀 배포 Backend를 통해 실제 LLM 규칙 초안 생성**을 사용할 수 있도록 만든다. 심사위원은 LLM API 키를 발급하거나 입력하지 않는다.

```text
심사위원의 클론한 앱
    → 팀 배포 Backend
    → LLM API (팀 서버의 키)
    → 규칙 초안 반환
    → 보험사 수정·검토·최종 승인
```

- 레포에는 배포 Backend의 공개 주소를 기본 설정으로 넣는다. 주소는 배포 후 정하며 현재 동작하는 URL은 없다.
- 실제 LLM 키는 팀 서버의 환경변수 또는 Secret에 보관한다. GitHub·Frontend 번들에 넣지 않는다.
- 모델·프롬프트·규칙 출력 형식은 팀 Backend에서 관리해 팀과 심사위원이 같은 처리 경로를 사용한다. 생성 결과의 매회 동일성을 뜻하지 않는다.
- 심사 시 인터넷 연결과 접근 가능한 팀 서버가 필요하다. 팀이 호출 사용량과 서버 운영을 관리한다.
- LLM 결과는 초안이며 보험사가 승인한 규칙만 계산·증명에 적용한다.
- LLM 실패 시 수기 입력 후 동일한 검토·승인 경로를 사용한다.

## 추천 후보와 미정 사항

- Gemini는 연결된 채팅에서 검토한 공급자 후보다. 최종 공급자·모델·API 버전·요금제·호스팅은 아직 선정하지 않았다.
- 서버는 규칙 초안 생성 용도로 제한하고 입력 크기·호출 횟수·전체 사용량 제한을 두는 구성을 추천한다. 구체 제한값·API 계약은 구현 시 정한다.
- 팀 서버 없이 직접 재현하는 로컬 Backend의 자체 키 방식은 선택 실행안이다. 기본 심사 경로의 필수 설정이 아니다.
- 사전 생성한 예시 초안 제공은 장애 대비 제안이다. 채택할 경우 실제 LLM 생성과 구분해 표시한다. 수기 입력 대체 경로는 확정이다.
- 무료 사용 범위 활용은 검토 사항이며 총비용 0원으로 확정하지 않는다.

## 제출 전 확인할 완료 기준

1. 제출할 커밋을 새 디렉터리에 클론한다.
2. LLM API 키가 없는 실행 환경에서 README의 준비·실행 절차를 따른다.
3. 로컬 앱에서 약관을 입력하고 팀 서버를 통해 실제 규칙 초안이 반환되는지 확인한다.
4. 초안을 수정·검토·승인하는 경로와 LLM 호출 실패 시 수기 입력 경로를 확인한다.
5. 검증한 런타임·패키지·컴파일러·Runtime 조합, 준비 명령, 배포 서버 의존성을 README에 기록한다.

이 기준은 향후 검증 항목이다. 현재 실제 호출·배포·새 클론 실행이 성공했다고 표시하지 않는다. LLM 키 입력 제거와 계약 빌드·증명 재현은 각각 확인한다.
