## 데모 영상 구성 결정 (2026-09-18, 확정)

사용자 앱에는 변조 버튼·장애 유발 기능을 넣지 않는다. 영상은 세 장면으로 구성한다.

1. 정상 흐름: 난수 모의 운행 2건 → 증명 유효 → 조건 충족 → 보험사 승인.
2. 정상 계산·조건 미충족: 증명은 유효함을 표시해 `증명 유효 ≠ 할인 승인`을 구분.
3. 변조 검증: 앱 밖(터미널 테스트 실행)에서 정상 데이터를 복사해 점수·이전 상태·규칙 해시를 바꾼 입력이 증명 생성 또는 검증에서 거부되는 로그를 보여줌.

3번 장면 뒤에 한계 문장을 반드시 넣는다: "ZK는 제출된 기록에 승인 규칙이 올바르게 적용됐다는 계산 관계를 보장한다. 기록이 실제 주행에서 나왔는지는 보장하지 않는다." (`PROJECT_DIRECTION.md` "검증의 한계"와 동일 취지)
