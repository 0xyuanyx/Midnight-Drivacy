# Repository instructions for coding agents

Before project work, read `PROJECT_DIRECTION.md` and `README.md`.

Before insurer web work, read `docs/WEB_APP_RULES.md` and `docs/WEB_IMPLEMENTATION_PLAN.md`. Build shared typography/layout/state components before screen variants. Latest approved refinements override Figma inconsistencies. Do not confuse Figma measurements with proposed token values, or mock UI verification with cross-app/API integration.

For mobile work, read `docs/MOBILE_APP_RULES.md`. Latest user-approved app refinements take precedence over Figma coordinates. Reuse semantic typography and shared layout components; do not reintroduce per-screen font metrics or undo fixed eyebrow/CTA placement. Propose grounded improvements when Figma is incomplete, and record accepted decisions.

For future conversations about this repository, record newly agreed project direction in `PROJECT_DIRECTION.md` as part of the relevant task. Distinguish decisions from suggestions and unresolved questions. Update the date; keep the README aligned when scope, implementation status, or run instructions change. Do not claim a planned Midnight proof or integration exists until it has been built and verified.

Preserve the manual insurer rule-entry decision for the hackathon demo unless the user changes it. Do not add LLM/document conversion to the MVP by inference. Keep the limits of what a proof establishes explicit.
